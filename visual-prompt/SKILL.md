# visual-prompt

Этот скилл не рисует. Он пишет **промты, которые исполняет skill `/anatomy`**, и хранит их в базе сайта.
Рисует всегда anatomy: каждый промт в базе начинается с `/anatomy` — схема (`schema/prompt.schema.json`) это проверяет.

## Режимы

| Вызов | Что делать |
|---|---|
| `write <идея>` | Написать промт по шаблону ниже и показать его пользователю. Файлы не трогать. |
| `add <идея>` | Написать промт, сохранить `prompts/<id>.json`, запустить `npm run validate`. Пример — только если пользователь попросит (это долго: Figure до часа, Hero 2–4 часа). |
| `add <id>` (id уже есть в `prompts/`) | Выполнить промт этой записи через skill anatomy с переменными по умолчанию, положить результат в `public/examples/<id>.html` (и `<id>-light.html`), прописать `example` в записи, запустить `npm run validate`. |

Без режима: если пользователь описал идею — `write`; если сказал «в базу», «сохрани», «добавь» — `add`.

## Как написать промт

1. **Найди механизм.** anatomy объясняет идею настоящим предметом: станок, прибор, механизм, мебель. Подбери предмет, работа которого один в один совпадает с идеей, и скажи одним предложением, что движется и что это значит. Посмотри таблицу соответствий в `references/objects.md` и существующие записи в `prompts/` — не повторяй уже занятые предметы.
2. **Собери правду.** Реальные числа: размеры, количества, пороги, скорости, формулы. Всё, что фигура показывает в readout, должно из них считаться. Числа, которые пользователь захочет поменять, вынеси в переменные `{name}`.
3. **Выбери формат и размер** (`references/formats.md`): `svg` — отдельный статичный .svg; `html` — живая интерактивная фигура; `webgl` — когда нужен огонь, вода, свет, свечение или 3D-поворот. Размер `figure` (40–80 деталей) по умолчанию, `hero` (80–150) только для плотных объектов или нескольких WebGL-слоёв. Epic в базу не кладём.
4. **Заполни шаблон** из `references/template.md` целиком: объект, движение, числа, детали по группам (основание, конструкция, механизм, органы управления, предмет-акцент), карточка (Fig, заголовок, подсказка, readout), движение и управление, строка вывода для формата, строка проверок.
5. **Чек-лист качества** для записи: 3 общих пункта из `references/template.md` + 1–3 пункта, специфичных для этой фигуры (что именно легко сделать неправильно).

## Запись в базу

- `id` — kebab-case по-английски, совпадает с именем файла.
- Первым ключом `"$schema": "../schema/prompt.schema.json"`.
- `title` ≤ 60 символов, `summary` 1–2 фразы: идея + предмет, который её несёт.
- `category` — одна из уже используемых, если подходит (см. `grep -h '"category"' prompts/*.json | sort -u`).
- Каждая `{переменная}` в `prompt` объявлена в `variables` и наоборот; у переменной с `options` значение `default` входит в `options`. Почти всегда есть `theme` с вариантами `тёмная` / `светлая`.
- `createdAt` — сегодняшняя дата `YYYY-MM-DD`.
- После записи: `npm run validate` должен закончиться `N/N записей в порядке`. Исправь все ошибки, не ослабляя схему.

## Генерация примера (`add <id>`)

1. Подставь в промт значения по умолчанию, тему возьми `тёмная`.
2. Выполни его как запрос к skill anatomy (вызови Skill `anatomy` и следуй его workflow полностью, включая audit, line check и 4× крупные планы). Скажи пользователю размер и время, как требует anatomy.
3. Собери обе темы (`build.mjs` и `build.mjs --light`) и скопируй standalone-страницы в `public/examples/<id>.html` и `public/examples/<id>-light.html`; для формата `svg` — `.svg`-файлы.
4. Пропиши в записи `"example": { "dark": "examples/<id>.html", "light": "examples/<id>-light.html" }`, запусти `npm run validate`, затем `npm run dev` и проверь карточку.
5. Исходники фигуры (build.mjs и модули) храни в `figures/<id>/`, чтобы пример можно было пересобрать.
